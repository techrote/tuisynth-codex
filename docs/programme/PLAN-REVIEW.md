# Programme plan review

## Initial plan
Retain the original 17 technical phases in fresh provider repos; one provider owns the whole programme.

## Review and improvements
| Finding | Improvement |
|---|---|
| old plan assumed many local/free workers | same provider owns dependencies and all phases |
| local-only CI | hosted Ubuntu/Windows x Python 3.11/3.14 PR matrix |
| one model/issue provenance | role-based model/subagent/tier provenance |
| monolithic whole-project prompt would harm resumability | keep 17 stable issues |
| exact internal layout risks transcription benchmark | behavior/public contracts fixed; architecture may improve |
| too much freedom harms comparison | preserve synthesis/parameters/gestures/acceptance |
| optional stretch creates unequal finish line | TRIO-015/016 mandatory |
| historical source absent | restate regression lessons locally |
| CI cannot prove hardware/listening | separate software qualification/physical acceptance |
| interrupted sessions expected | mandatory checkpoint format |
| multi-tier reviews expected | record review role/config |
| issue/docs may diverge | explicit authority order + same-PR RAG updates |

## Improved plan
Seed equal RAG docs; only attempt identity differs. TRIO-001 establishes packages/check tool/four-lane CI. Shared foundation precedes three distinct instrument paths. Extensions are mandatory. TRIO-017 releases software-qualified wheels/docs/launchers while physical acceptance remains manual. Every issue closes only after merged exact-head green PR + post-merge main verification.
